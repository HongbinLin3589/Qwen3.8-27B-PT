# 4.2 数据处理流程：依据核对与最小可行方案

核对日期：2026-10-16。标记含义沿用项目约定：【论文】有论文或实验结果支撑；【理论】有理论依据；【计划】来自本项目计划，没有外部出处；【推论】基于已有研究的推论；【猜想】Claude 自己的判断；【记忆】确有已发表研究，但本次没有重新核对原文。

## 一、原文里的数字

| 原文说法 | 核对结果 | 出处 |
| --- | --- | --- |
| CodeMidas：完整过滤的 3K 任务全面胜过未过滤的 8K 任务 | **属实**【论文】。从过滤后的任务池随机抽 3K，在 SWE-bench Pro、DeepSWE 和内部验证集上都高于约 8K 的未过滤样本；完整的 5,545 个任务分别高 0.59、4.59、4.49 分。**但论文没有逐项消融**，无法说明哪一道过滤最有用 | [CodeMidas §3.3–3.4 与消融](https://arxiv.org/html/2609.22068v1) |
| 6 个全新容器：2 个初始状态必须失败，4 个参考答案必须通过 | **属实**【论文】 | 同上 §3.3 |
| 约 20 个共同上游源；1.45M 条中有 36,148 条泄漏 | **数字属实，措辞要改**【论文】。论文把 1,450,827 条追溯到 20 个原子源，并报告发现 36,148 条泄漏。但它没有说泄漏扫描覆盖了全部 1.45M 条。泄漏检测用的是 Sentence-BERT 嵌入检索加人工核对，图中只统计相似度 ≥ 0.9 的高置信样例 | [RLVR Datasets and Where to Find Them](https://arxiv.org/abs/2605.26971) |
| Orchard：SFT 加 RL 把 SWE 成功率从 22.0% 提到 67.5% | **只有 67.5% 能对上**【论文】。67.5% 是 Qwen3-30B-A3B-Thinking 在 SWE-bench Verified 上 SFT+RL 后的成绩；只做 SFT 就有 64.3%，RL 只多 3.2 分。全文没有找到 22.0%。另外，第四章数据表里的「Orchard」指向一个 HuggingFace 轨迹数据集，和这篇微软论文可能不是同一个东西，需要确认 | [Orchard 论文](https://arxiv.org/abs/2605.15040) |
| 「这是对强起点模型最重要的一步」（难度过滤） | **没有直接证据**【推论】。CodeMidas 没有拆开各项过滤的贡献。只能说「去掉全对和全错的题」被多家采用 | 见第二节第 5 行 |

建议改写：
- 第 2 步改为「对 1.45M 条公开 RLVR 数据的追溯中发现 36,148 条与评测集高度相似（≥ 0.9）」。
- 第 7 步（Orchard）改为「SFT 后 64.3%，再加 RL 到 67.5%（Qwen3-30B-A3B，SWE-bench Verified）」，删掉 22.0%，或者补上它的出处。

## 二、每一步的依据和最小方案

| 步骤 | 业界怎么做 | 依据 | 最小方案 |
| --- | --- | --- | --- |
| 2 训练集内部去重 | 普遍做精确去重；近重复去重常见，但阈值各家不同 | 精确去重【论文】（上面的 RLVR 追溯论文用 SHA-1）；近重复阈值【记忆】 | **只做精确去重**。在 math2code 试点上，文本近重复会把「2×n 铺砖」和「3×n 铺砖」合并（本项目实测，见 README），所以近重复默认关闭 |
| 2 对评测集去污染 | 嵌入检索加人工核对；n-gram 重叠是老做法 | 嵌入【论文】（RLVR 追溯）；13-gram【记忆】（GPT-3） | **保留**。13-gram 加嵌入，命中的样本人工抽看 |
| 2 时间切分 | SWE-rebench 按 issue 时间和模型发布时间标记可能污染的评测 | 【论文】[SWE-rebench §2](https://arxiv.org/html/2505.20411v2) | **保留**，只有一个日期参数 |
| 2 按仓库切分 | 没找到直接论文 | 【推论】 | 保留，成本几乎为零 |
| 3 执行一致性 | SWE-rebench：每个任务跑一次，要求失败到通过、原本通过的仍通过；CodeMidas：6 个容器，2 次初始状态加 4 次参考答案 | 【论文】两者都有 | **保留**。2+4 有出处；如果成本紧，可以先 1+2【猜想】 |
| 4 测试不锁死措辞 | SWE-bench Verified 人工标注后筛掉 68.3% 的样本，其中 61.1% 被标为测试过严、会误判正确解 | 【论文】[OpenAI](https://openai.com/index/introducing-swe-bench-verified/) | 问题真实存在，但我写的正则检查**没有出处**【猜想】，**删掉** |
| 4 审查 agent 找假阳性 / 假阴性 | CodeMidas：每题 4 次解答，审查 agent 对照题面判断 | 【论文】 | 保留但**合并**：直接复用难度过滤的采样，不单独再采【推论】。没有审查 agent 时先跳过 |
| 4 每源人工抽检 100–200 条 | 没找到出处 | 【计划】 | 改成每源先看 30–50 条，发现问题再加量【猜想】 |
| 5 清理产物与缓存 | CodeMidas 删除编译产物、缓存副本、建题 agent 留下的文件和原有测试 | 【论文】 | **保留** |
| 5 走捷径检查 | CodeMidas 让 agent 专门找捷径。另一篇审计发现，五个开源模型在 SWE-bench Multilingual 上 45–82% 的轨迹在利用 git 历史、上游仓库或背过的答案；提示里要求「原创解答」可降到 4–11% | 【论文】[CodeMidas](https://arxiv.org/html/2609.22068v1)；[Shortcutting the Fix](https://arxiv.org/abs/2609.06780) | **保留便宜的部分**：删掉 git 未来历史、断网、提示里加原创要求、grep 残留答案。LLM 捷径 agent 先不做 |
| 6 难度过滤 | CodeMidas：保留至少一次通过且至少一次失败的题；DAPO：动态丢掉全对或全错的组 | CodeMidas【论文】；DAPO【记忆】 | **单轮**：采 8 次，保留 1–7/8。全错的交给教师，全对的丢弃 |
| 6 分档 4→8→16/32、留 10–15% 锚点 | 没找到出处 | 【计划】 | **去掉**追加采样和锚点，以后有需要再加 |
| 8 教师轨迹拒绝采样 | 只留验证通过的轨迹；Orchard 的 SFT 是主要涨幅来源 | 【论文】（Orchard：SFT 后 64.3%）；拒绝采样微调【记忆】（SWE-Gym） | **保留**：验证通过、没截断 |
| 9 学生与教师 log-prob 都存 | OPD 需要教师逐 token log-prob；离线 RL 的重要性比需要采样时的 log-prob | 【理论】 | 只存**采样模型自己的** log-prob，采样时零成本拿到。另一方的打分等做 OPD 时再补算【推论】 |

## 三、代码里已经怎么改

新增 [`configs/data/minimal.yaml`](../../configs/data/minimal.yaml)，没有动默认配置：

- 关掉训练集内部的近重复去重和测试正则检查。
- 泄漏检查只做清理、复查参考答案和 grep 找残留答案，不跑 LLM agent。
- 难度插件仍默认关闭；打开时改为单轮采 8 次，没有追加采样，没有锚点，全对的丢弃。

在样例数据上，这套配置仍能剔除精确重复、评测污染、截止日期之后的题、评测仓库、不一致的环境、假阳性和假阴性，以及把答案留在仓库里的题。代价是「稍微改写过的重复题」会留下来。

还没做、但值得做的一项：让验证器审查直接复用难度过滤的采样，省掉一轮采样【推论】。
