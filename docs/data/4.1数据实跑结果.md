# 4.1 数据实跑：POLARIS-53K + DeepCoder 代码题

## 1. 下了哪些数据

开发环境连不上 Hugging Face（huggingface.co 返回 403），但 `git clone` GitHub 可以。所以我逐个检查了 4.1 表中各数据集的 GitHub 仓库，只有两项把训练数据直接提交在仓库里：

| 表中条目 | 实际来源 | 训练题 | 许可证（仓库 LICENSE，已核对） |
| --- | --- | --- | --- |
| 数学：POLARIS | `ChenxinAn-fdu/POLARIS` 的 `parquet/stage1/polaris-data-53K.parquet` | 53,291 | Apache-2.0 |
| 代码：DeepCoder | `agentica-project/rllm` 的 `deepcoder` 分支 `rllm/data/train/code/*.json` | 14,030（LeetCode 1,889、Codeforces 6,128、APPS 2,437、CodeContests 3,576） | MIT |

注意：DeepCoder 这份是 rllm 仓库里提交的代码训练数据，不是 HF 上的 DeepCoder-Preview-Dataset（那份由 TACO、PrimeIntellect、LiveCodeBench 组成）。

下面这些仓库我也拉了文件树，但里面只有代码、评测集或示例，没有训练数据文件，数据只放在 HF 上：SWE-Gym、SWE-smith、R2E-Gym、Search-R1、DeepMath、Big-Math、Skywork-OR1、DAPO、KodCode、open-r1、OpenThoughts-Agent、SETA。

用来去污染的评测集，同样取自这两个仓库：AIME24、AIME25、AMC23、Minerva、OlympiadBench、MATH-500、HumanEval+，以及 LeetCode、Codeforces、CodeContests 的测试题，共 2,526 条。表中提到的 LiveCodeBench 拿不到（只在 HF 上），所以没能对它去污染。

## 3. 去污染：第一次跑出来的结果几乎都是误判

按原方案（13-gram 只要撞上一个就算污染），第一次跑去掉了 11,726 题。我抽样检查后发现，绝大多数是题面套话撞上了：

- CodeContests 题面末尾都有 `Time Limit: {'seconds': 2, 'nanos': 0} Memory Limit: 256000000 Bytes`。
- LeetCode 每题开头结尾都有相同的说明，例如 "Please solve the programming task below using a self-contained code snippet in a markdown code block."
- POLARIS 有 4,559 题末尾带 "Let's think step by step and output the final answer within \boxed{}."，评测集每题也都带这句。
- 标点和 LaTeX 符号也各算一个词，导致 `$ a $ , $ b $ , and $ c $ ,` 就能凑满 13 个 token。

改了以下几处（都是配置项，在 `configs/data/math_code.yaml` 里）：

1. 比对前先去掉套话（`ignore_patterns`）。"think step by step" 这句在下载时就从题面里去掉了，导出时再统一加回去。
2. 只用单词切 13-gram，不把标点和符号算进去（`word_tokens: true`）。
3. 出现在 3 道以上评测题里的 13-gram 视为套话，忽略（`max_eval_df: 3`）。出现在 50 道以上训练题里的也忽略（`max_train_df: 50`）。
4. 两题共有的 13-gram 要占较短一题的 20% 以上才算污染（`min_overlap: 0.2`）。

改完后去掉 117 题。我逐条看了 AIME、AMC、LeetCode 的命中和一批 OlympiadBench、MATH-500 的命中，大多是同一道题的不同排版（`$...$` 对 `\(...\)`，`\geq` 对 `\geqslant`）。仍有大约 5 道是误判，比如 AIME 那句很长的 "can be written in the form m√n/p where m, n, p are positive integers ... Find m+n+p"，以及 LeetCode 里两道都定义了 "beautiful string" 的题。多去掉几道训练题的代价很小，所以这次没有继续调。

漏判的风险依然存在。例如 "sin²4° + sin²8° + … + sin²176°" 在 POLARIS 和 OlympiadBench 里都有，只是写法不同，13-gram 只撞上 1 个，重合比例 0.17，没有被去掉。这次用的本地哈希向量太弱，抓不住这种情况。【推论】正式使用应换成真实的向量模型，或者对重合比例在 0.05–0.2 之间的题对加一道 LLM 判断。

【推论】第一次跑的结果说明，表中「DeepCoder 含 LiveCodeBench 题，评测时须排除」这类问题不能靠「撞一个 13-gram 就删」来解决：在代码题上，这个规则会把大半数据当成污染。

## 4. 发现的数据质量问题

- **POLARIS 证明题**：约 3,400 题是证明题，ground_truth 是凑出来的（例如 `1`、`(,b,)`、`\trianglePQR`、`S_{2001}=2S_{2000}+1`），答案匹配判不了。我在下载时用规则排除了题面含 prove 或 show that 的题。这条规则也会误伤少量「求值并说明」的可判题。【推论】证明题要按表中所说另建评分，不应进入答案匹配的 RL。
- **Codeforces 题面含算法标签**：题面末尾带 `Tags: ['greedy', 'dp']`，相当于直接提示解法。下载时已从训练题和评测题里去掉。
- **Codeforces 文件里有 2,868 条完全重复**：题面和测试都一样，去重时已处理。
- **stdin 题的判题方式**：判题器逐词比较输出，浮点数允许 1e-6 的误差。需要特判的题（"if there are multiple answers, print any"）会被误判成错，对这类题的奖励会偏低。
- **CodeContests 题面里有字面的 `<image>`**：共 1,142 题，原图已被数据集去掉。verl 会把 `<image>` 当成图片占位符，导致 RL 行的格式检查失败。下载时已替换成 `[image not available]`。这类题可能缺了解题需要的图，接上模型后的难度过滤会把做不出来的筛掉。
- **APPS 函数题**：约一半题面里没有写函数名，导出时在题面末尾加了一句 "name it `函数名`"，否则模型无从知道测试会调用哪个函数。
- **LeetCode 参考解依赖**：参考解会用到 `sortedcontainers`，以及 `operator`、`string`、`datetime` 里的函数。判题环境需要装 `sortedcontainers`，并带上这些 import（已写进 `LEETCODE_PRELUDE`）。

## 5. 产出（verl 格式）

| 文件 | 行数 | 说明 |
| --- | --- | --- |
| `rl/train.parquet` | 58,419 | verl 标准 RL 格式 |
| `sft/reference.parquet` | 1,868 | LeetCode 题 + 参考解，`messages` 格式 |
| `sft/invalid.jsonl`、`rl/invalid.jsonl` | 0、0 | 没有格式检查失败的行 |
| `export_report.json` | | 按 verl 的方式读回后与写入时的差异：这两个文件没有差异 |
| `run/dropped.jsonl` | 5,487 | 每条被去掉的题和原因；去污染的记录里带对应评测题的 id 和一个共有的 13-gram |
| `data/manifest.json` | | 下载来源、提交位置、行数 |

四种判题方式在 `reward_model.ground_truth` 里的写法：

- 数学（`answer_match`）：答案字符串，例如 `"9375"`。
- LeetCode（`python_asserts`）、APPS（`python_function`）、Codeforces / CodeContests（`stdio`）：JSON 字符串，内容是测试用例和判题方式。

`src/qwenpt/data/export/verl_reward.py` 里的 `compute_score` 能直接判这四种。我用 200 道 LeetCode 参考解试过，200 道都得 1 分。数学题拿正确答案得 1 分，拿错误答案得 0 分。

## 6. 复现

```bash
python -m pip install sortedcontainers   # LeetCode 参考解要用
python -m qwenpt.data download --sources configs/data/sources/math_code.yaml --out data/pipeline/math_code   # 约 35 秒
python -m qwenpt.data run    --data data/pipeline/math_code --config configs/data/math_code.yaml --out runs/math_code   # 约 4 分钟
python -m qwenpt.data export --run runs/math_code --config configs/data/math_code.yaml --out export/math_code
```
